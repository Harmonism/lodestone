# Lodestone — desktop app

*The code-level reference for Lodestone Desktop.*

Lodestone as an ordinary application on macOS, Windows and Linux, carrying the harmonism.io library with it. The practitioner installs it, double-clicks it, and a Lodestone window opens. Nothing else is installed, no Terminal or browser is involved, and no address is shown.

Everything ships inside the app: the web app from `../app/` (unchanged apart from a desktop mode), the corpus pack, the retrieval model, the model engine, and the English site. The only thing not shipped is the language model, which is several gigabytes. The first launch downloads it once, with a progress bar, and checks every file against the hash Hugging Face publishes.

The app uses a *MunAI Offline* data folder where it finds one (model, conversations, practices, memory), and on macOS offers to move the old `MunAI Offline.app` to the Bin.

## What the practitioner sees

1. **First launch.** A welcome window recommends a model for the computer's memory and offers one button, *Download and begin*. The download shows size, speed and time left; a pause resumes where it stopped, across restarts; busy servers are retried. Below 16 GB of memory the window says Lodestone may be slow or not start.
2. **Every later launch.** "Waking Lodestone" for a few seconds, then the conversation. In a wide window the conversations list stays docked on the left — visible through everything, until it is folded away from the ☰ button or the drawer's × (the choice is remembered).
3. **The library.** The book icon in Lodestone, or *Lodestone → The Library* (⌘2 / Ctrl+2), opens harmonism.io as it is online, served from the app: every English page, the search, the interactive Wheel and the assessment. The companion in the corner of each page is answered by the local model, with the page as context and no seven-message limit. Account and membership pages say they live on harmonism.io and link there; narration audio plays from harmonism.io when online. Links to harmonism.io inside Lodestone's answers open in the library.
4. **Other languages.** A French (or other) page that is not installed offers to download that language (French ≈ 50 MB); *Lodestone → Library Languages and Updates…* lists them all.
5. **Updates.** Same screen: *Check* asks harmonism.io whether a newer corpus and doctrinal backbone, or a newer English library, is published; one button fetches it. Nothing is ever checked by itself. While the site is behind its beta password, the password is asked once and kept encrypted by the operating system's keychain.
6. **Look this up online.** The globe beside the message box, per question, off by default, with a one-time explanation. The question goes to DuckDuckGo (Wikipedia when DuckDuckGo does not answer; Brave Search instead if `"braveKey"` is set in `desktop.json`), the top three pages are read from this computer, and Lodestone answers with them in a `<web_results>` block beneath the corpus, citing each site.
7. **The model menu, under the message box.** Shows the model Lodestone is thinking with; one click lists every model downloaded on this computer and, once an API key is saved, the rented models: the four hosted Lodestone runs on (recommended, tested with Lodestone), the last ones used, and a field for any other model id. The switch happens in place and the conversation continues; a line in the chat marks it (never sent to the model). Switching to a model on this computer keeps the saved key, so switching back asks for nothing.
8. **Lodestone → Model…** Switch, download or remove models; *Advanced* adds any `.gguf` from Hugging Face by pasting its link (split models by their first part; every part hash-checked), or points Lodestone at a model server of the practitioner's own.
9. **Lodestone → Use from Your Phone…** Opens Lodestone to the local Wi-Fi and shows a QR code. Below it, **Telegram**: the practitioner's own bot (from @BotFather), paired by a six-digit code, answered through the same harness. Since 1.12 it reads what is sent to it as the window reads an attachment: documents, photos, recordings, videos and voice messages, fetched from Telegram (20 MB at most, Telegram's limit for bots; a larger file is answered with that reason) and read by the hidden page with `attach.js`; a voice message with no caption is what was said, its transcript the message. A kind it cannot read (a sticker, a location) is answered, not met with silence.
10. **A model you rent.** *Lodestone → Model… → A model you rent, with your own API key*, also offered on the welcome screen. Anthropic (native Messages API, the system prompt's stable part cached), Venice, OpenRouter, Hugging Face (`router.huggingface.co/v1`, open-weight models, an `hf_` token; no per-request data-retention switch, so its providers' own terms apply) or any OpenAI-compatible provider. The key is tried with one short request, then kept encrypted by the keychain. Retrieval, the crisis gate, witness mode, memory and practices stay local; each turn's assembled context goes to the provider. Lodestone's persona and the settings drawer say so (`whereLine()` in `app/js/prompt.js`).
11. **Attachments (1.12: all kinds of files).** The paperclip beside the message box (its picker shows every file), drag and drop anywhere in the window (the window says it takes them; a dropped folder gives its readable files, hidden ones and dependencies left out), or paste anywhere but another field (a file copied in the Finder or Explorer, a screenshot). Up to 20 wait at once; the same file twice is attached once. Read on this computer before any model sees them (`app/js/attach.js`, the same on the web app and the phone): text and code of any kind, and any file that turns out to be text whatever its name (UTF-8, UTF-16 with or without its mark, Windows-1252); web pages and RTF by their words; PDFs by pdf.js 6.3.289 (legacy build, vendored in `app/vendor/pdfjs/`), a scanned PDF's first four pages shown as images to a model that can see; Word, Excel and PowerPoint (`.docx .xlsx .pptx`: paragraphs and table cells, sheets by name with cells in their columns, slides in order with their speaker notes), OpenDocument (`.odt .ods .odp`), EPUB in its reading order, Pages, Numbers and Keynote by the PDF preview inside them, all read part by part from inside the file (a small zip reader over `Blob.slice` and the browser's `DecompressionStream`, never the whole file in memory, each part stopped at 64 MB so a file that unpacks into gigabytes reads as what it is); `.zip` archives, up to 25 readable files inside; old Word (`.doc`) by its text runs, said so. On the desktop, `src/convert.js` converts what a browser cannot open, on this computer: on a Mac `textutil` (old Word, RTFD, web archives) and `sips` (HEIC, TIFF, PSD, camera RAW, JPEG 2000, to a JPEG of 1,568 px); anywhere, LibreOffice when installed (old Word, WordPerfect, Works to text, old Excel to CSV, old PowerPoint to PDF), run with its own profile and no shell. Recordings, and the sound of videos (MP4, MOV, WebM), decoded at 16 kHz and transcribed by Whisper small in a worker (`asr-worker.js`) ten minutes at a time, each cut at the quietest half-second near the mark, so the progress shows (*part 2 of 5*); its 250 MB downloaded once on first use from a pinned Hugging Face revision and hash-checked (`src/speech.js`), told the language from the app setting or the system. Images scaled to 1,568 px (turned as the camera held them) and sent only to a model that can see. Limits are on what the device can hold, said with the file's size when it is over: PDFs, documents and archives 300 MB, images 80 MB, recordings and videos 1.5 GB and 90 minutes on the desktop (400 MB and 45 minutes on the web app and the phone, which decode in less memory); a text file is never refused, its first 8 MB read and marked shortened. A file of a kind Lodestone cannot read says which kinds it can. Gemma models gain sight with their vision projector (`mmproj` in `models.js`, downloaded on first image, passed to `llama-server --mmproj`); Anthropic always sees; other providers are tried. Document text goes in an `<attached_files>` block (60,000 characters a file, shared out by the window's budget) and stays available to the next three turns; images are sent once and never stored. A short recording with nothing typed becomes the message, to read over before sending. Pasting a Harmonic Profile code (`HP::…`) fills the Wheel reading and the assessment summary (`app/js/hp.js`, port of the Telegram parser), in the window and in Telegram.
12. **Folders Lodestone may read.** Settings → Advanced lists folders the practitioner adds one by one (never the home folder or a disk root). For each message in Lodestone's own window, `src/folders.js` finds the passages that bear on it in their Markdown, text and Org files; Lodestone cites the file and quotes exactly, and the files used show under the answer. Read-only, no symbolic links followed, never searched for the Telegram bridge; Settings says whether the passages stay on the computer or travel to a rented model's provider.
13. **A harmonism.io account.** *Lodestone → Model…* → *Your harmonism.io account*: email and password of the website's own account (`src/hosted.js`; refresh token in the keychain). Lodestone then thinks with the hosted models, ten messages a day in total across the website, Telegram and the app, counted by the server; the chip shows how many are left. The turn is assembled here as with a rented model and goes to `harmonism.io/lodestone-desktop-api.php`, which puts the server's own doctrinal backbone in place and stores nothing. A closed-weight model chosen under the practitioner's own key is labelled *closed weights · not tested against the doctrine*.

14. **Conversations (1.10).** Each row of the docked list has a ⋯ menu, also on right-click: *Rename* (or double-click), *Pin*, *Export as Markdown*, *Delete*. Pinned conversations sit under their own heading. A search field above the list matches names and the text of every message, with the matching line shown. A rename and a pin carry their own time (`titled`, `pinSet` on the thread), so sync keeps the later one (`merge()` in `app/js/sync.js`). The last exchange can be taken back: *Retry* asks again, *Edit* returns the question to the message box; an exchange with attachments cannot, since their text is not kept. *Stop* (or Esc) keeps what was written, marked *stopped*. ⌘N a new conversation, ⌘F find one, ⌘, Settings.
15. **Usage and costs (1.10).** Each answer keeps the usage its provider reported (`meta.usage`: tokens in and out, and the cost in dollars where given). The page asks for it with `stream_options.include_usage`; `remote.js` adds `usage: { include: true }` for OpenRouter, which then reports each answer's cost; the phone route does the same (`OpenRouterEngine`). A model on this computer reports tokens and costs nothing; Anthropic's translated stream carries no usage yet. Shown on each answer, as a running total under the message box, beside each conversation in the list, and by period and model in *Usage and costs* (from the total or Settings). Summaries of long conversations are counted on the thread (`side`). An optional monthly limit for rented models (Settings) stops sending past it, with a card to raise it, and warns at 80%; it counts on this device, so the key's own limit at openrouter.ai stays the hard one. A stopped answer reports no usage, though the provider may still bill what it generated.
16. **Dictation (1.10).** The microphone beside the message box, or ⇧⌘D: speak, click ■, and the text lands at the caret, unsent, to read over; or press send while it listens, and what was said is written out and sent with whatever was typed, in one press. Esc discards. What was said is cleaned in three layers. The sound: Silero VAD v5 (MIT, 2.2 MB, `app/vendor/models/onnx-community/silero-vad/`, run through the transformers.js already shipped) keeps only the stretches where someone speaks, in `asr-worker.js`, so Whisper never hears silence or noise, where it writes stock phrases ("you", "Thank you for watching"); a recording with no voice is nothing. The sound is not denoised: denoising makes Whisper less accurate. Whisper: primed, through its decoder's opening tokens, with a sentence of the corpus's terms in the speaker's language (English, French, Spanish, Portuguese, German), which in tests spelled Lodestone, Harmonism, Ṛta, Sushumna and Qi where unprimed Whisper wrote "Loadstone", "Rita", "Sashamna"; a bare list of terms made it worse and is not used. The words (`app/js/tidy.js`): hesitations in six languages, stutters, repeated short words, Whisper's tags and loops, capitals and commas, with emphasis ("no no") and words that only look like hesitations ("uh-huh", "'em") left alone; then, on a rented model or one on this computer, one pass by that model for what rules cannot do, a speaker changing their mind ("at five, actually six"), under a clean-verbatim prompt, its answer refused and the rules' version kept when it answers, translates, rewrites or cuts (`acceptCleanup`), and after 12 s. Never on words with a crisis or care phrase, a key or a card number, nor on the browser's own small model or the account's allowance. Settings → Dictation turns the rules and the model's pass on or off (both on). The conversation by voice gets the first two layers and the rules. Through OpenRouter, Whisper cannot be primed (the prompt is ignored there); the model's pass spells the terms. Tested in Chromium with real Whisper small and a Piper voice: noise and a fan hum gave nothing (before: "you"), a self-corrected sentence came out with only what was settled on, and a model that answered instead of cleaning was refused. Transcribed on this computer by the same Whisper small the attachments use (`transcribeClip()` in `app/js/attach.js`), downloaded once on first use with the practitioner's leave; the language comes from Settings → Dictation, else the reply language, else the system's. Lode sends the voice to a provider under a key; Lodestone does not. `NSMicrophoneUsageDescription` is in the Mac build's `Info.plist` (`package.json`).
17. **Back from the library.** Every library page carries *Back to Lodestone* at the bottom left, injected by `server.js` (`BACK_LINK`, since 1.2, so the phone's view of the library has it too); 1.10 lifts it above everything the site draws (z-index at the maximum, from 150). The conversation open before the visit opens again (`sessionStorage`, `lodestone-open-thread`).
18. **Settings (1.10).** Grouped cards with a gear in the toolbar: Model, Usage and costs, Spoken replies, Dictation, Folders, Appearance and language, Corpus, Your data, Sync, Help.
19. **Spoken replies (1.10).** The Telegram companion's modes, on the device's own voices (`app/js/voice.js`): *Text*, *Voice* (spoken, the text folded under a *Show the text* row), *Both*, *Mirror* (spoken when the message was dictated), and a female or male voice; a chip under the message box switches them, Settings → Spoken replies adds the voice per language and the speed. The operating system's speech synthesis reads the reply sentence by sentence as it is written, in the reply's language (`detectLang`), Premium and Enhanced voices first, novelty voices never; nothing is downloaded or sent. *Listen* on any answer; Esc or *Stop* silences it, and sending, stopping the answer or changing conversation does too. Crisis replies and witness mode are never spoken unasked, as on Telegram. Works in the web app as well, where the browser offers voices; *Mirror* needs dictation, so the desktop.
20. **Natural voices (1.11).** Answers are read by Grok's Ara and Rex by default wherever a natural voice can be reached: the OpenRouter key Lodestone thinks with (read through `syncKeyGet`), the harmonism.io account (the `voice-speak` handler, to `lodestone-voice-api.php`), or a key pasted for voice alone in Settings → Spoken replies (OpenRouter, xAI or OpenAI). ElevenLabs, Google Gemini and OpenAI voices can be chosen. With a model on this computer the computer's own voices read unless a voice key is saved or *Natural voice* chosen. An OpenRouter account limited to zero-data-retention providers refuses Grok; ElevenLabs then reads, the refusal is remembered on the device, and *Try Grok's voices again* forgets it. Code `app/js/voicecloud.js`, `voicePlan()` in `app/js/main.js`.

20. **Profile learning (1.10).** Every ten of the practitioner's messages, after the answer, three calls on the model in use (never on harmonism.io's hosted models, never with no model), with Telegram's prompts (`app/js/learning.js`, ported from `process-queue.php`): Lodestone's notes on the person (editable; an edit is kept and built on), the Wheel update under Telegram's evidence discipline and its bidirectional accumulator (a high-confidence change moves at once, low-confidence signals at two, opposite evidence cancels), and the conversation context (emotion, situation, current and pending threads, commitments). Their practice check-ins are read as evidence alongside the conversation. One departure from the Telegram prompt: the Wheel call also returns `evidence`, the words that moved a level, to show the practitioner. Every message also advances doctrinal fluency (#536) and bodily-register openness (#775), levels that only rise, read before they advance so a change shows on the next turn. The notes enter `<person_context>` marked as Lodestone's; fluency, openness and context enter as their own blocks. Your path → *What Lodestone has learned* shows all of it, with *Learn now*, *Forget what it learned* and a switch to stop learning. Stored as `learned` in the synced memory.
21. **The Wheel's movements (1.10).** A level the evidence moves is a proposal at the top of the conversation (*Yes, it has* · *Not yet* · *Talk it through*); the Wheel is the practitioner's, and nothing moves without them. An accepted rise is marked: a banner, the Wheel's score (the sum of the eight pillars, 0–48) in Your path, and a system notification when the window is not in front; a fall is accepted without ceremony. Their own corrections enter the same history. Nothing is scored for using the app, and the reading carries no score.
22. **The Wisdom Canon, on this device (1.10).** `app/js/canon.js` ports `companion-reading.php` and the kind decision of `reading-checkin.php`; the canon itself (`canon-data.js`) is generated from the PHP's `readingCanon()`. Your path → *The Wisdom Canon*: a work in the Threshold order or the Perennial Core, the edition's division count, pace, how often Lodestone asks, whether to talk about it, the usual hour; the plan is shown before the first page (days, the weekly taper, the close) and fixed then. *I have read it*, *Opened it* (three openings over more than a day without finishing turn the next question into one about the pace), margin notes in three seams. A check-in that comes due is folded into the next answer under the `<reading_arc>` instruction, as the website does; a slot more than 48 hours past is spent. Stored as `reading` in the synced memory; harmonism.io accounts keep their server arcs on the website, and the app no longer shows them.
23. **Writing first (1.10).** `app/js/outreach.js` ports `outreach-engine.php`: dormancy (quieter than the person's own rhythm), stagnation, readiness for the next phase of the Way of Harmony, resistance, a pillar gone silent, the solstices; one week between messages, confidence 0.70, one winner. Hourly while Lodestone is open, 9:00 to 21:00, composed on the model in use (never the hosted one) into a conversation of its own, *Lodestone wrote*, with a system notification when the window is not in front; the own Telegram bot asks the hidden page for the same before its practice check-ins, and the one log (`outreach`, synced) holds the week across both. Off in Your path.
24. **Share with your guide (1.10).** Your path → *Share with your guide*: the practitioner ticks what goes in (the Wheel and its movements, Lodestone's notes, their own words, practices, the Harmonic Profile, what they are in the middle of, the reading and its margin) and Lodestone makes a page to print or save as PDF, or Markdown, or copies it. Made on the computer and sent to no one; Telegram's `/share` code read the profile on the server instead.
25. **The privacy gate (1.12, after Lode's).** Before a message goes to a model that runs elsewhere (a rented model, the harmonism.io account), its words and its attachments' text are scanned on this computer (`app/js/privacygate.js`) for private keys, API keys and tokens (OpenRouter, Anthropic, OpenAI, xAI, GitHub, AWS, Google, Slack, Groq, Hugging Face, Stripe, Telegram, JWTs), password lines (`DB_PASSWORD=…`, `"password": "…"`, *mot de passe*), card numbers (Luhn-checked, an expiry after them allowed) and IBANs (checksum-checked). Found, a card shows each, masked, where it is: *Leave them out* (each replaced by a short marker, the rest sent as written), *Send as written*, or *Go back* (Esc; the words stay in the box). Over Telegram, with no one to ask, they are left out and the answer says so. A model on this computer sends nothing away, so nothing is asked there. Whatever was chosen, keys and private keys are never kept: the stored message and its attachments' text (synced, exported, re-sent on the next turns) carry the marker instead.
26. **The care layer and the pause bell (1.13; New York's AI-companion law, in force since 5 November 2025, and California's SB 243).** Behind the crisis gate, still on the device and before any model: indirect expressions by phrase (`INDIRECT` in `app/js/care.js`, four languages), and, where the meaning model is loaded, by meaning: a linear reading of the message's multilingual-e5-small embedding, fitted on 152 sentences (indirect ideation and self-harm against ordinary talk that comes close; data, fit and leave-one-out in `tools/care-fit/`: 75 of 78 caught, 8 of 74 hard ordinary sentences mistaken at 0.5, 3 at 0.8). Above 0.5 the model is told (`<care_check>`) to ask plainly and gently about safety if the message is about that, and otherwise to answer as asked; above 0.8, or on a phrase, the app itself adds the crisis line for the practitioner's country beneath the answer (`crisisLine()` in `safety.js`), a notice no model writes or reads. The pause bell: after three hours of a sitting (messages less than 30 minutes apart), once, and three hours after the last, a notice says Lodestone is an AI, not a person, and invites a pause; over Telegram it ends the answer (`presence.js`). Setup and Settings → Help say Lodestone is an AI, made for adults, that companion chatbots may not suit some minors, and link the published protocol (`app/safety.html`, also at `/lodestone-app/safety.html` on harmonism.io). `detectLang` now counts English's commonest words, so "everyone would be better off without me" is no longer read as French.
27. **Recall across conversations (1.13, after Kindroid's and Nomi's).** The practitioner's own words in earlier conversations, and each conversation's summary, embedded on this device by the meaning model and kept in this device's storage only (`recall:index`, never synced; each device builds its own, newest first, two thousand at most, out of the way of a conversation). A message brings back up to three passages from other conversations, two per conversation at most: close in meaning (0.83) and sharing a word of substance, or very close (0.89). They go to the model as `<earlier_conversations>`, to be used as memory, never as instructions; under the answer, *Remembered from:* names each conversation, opens it, and *Forget* keeps it from coming back. On by default where the conversation stays on the device; off until chosen where a rented model or harmonism.io reads each turn, since what is recalled travels with it (Settings → Your data, which says so). A moment of crisis or care is never indexed; what is taken back with Retry or Edit, and deleted conversations, leave the index. Only the window writes the index; the hidden Telegram page reads it afresh every ten minutes. Needs deep retrieval.
28. **Key memories in their own words (1.13).** A message beginning "remember that…" (*souviens-toi que*, *recuerda que*, *تذكر أن*) adds what follows, dated, to *What Lodestone knows about you*, once the crisis gate and the care layer have passed the message (a crisis or a care moment is never kept as a fact), and the message still goes; "remember when…", "remember to…" and a retried message are not taken; the model reads these notes as what the person asked it always to know, outranking anything inferred, 4,000 characters (the newest kept). *Remember this about me* under a message dates its note too.
29. **The week (1.13, after Rosebud's weekly reflection).** Off until chosen in Your path → *What Lodestone has learned*: at the day and hour chosen (Sunday at 18:00 by default), Lodestone writes a short examen of the week, into a conversation of its own, *The week · 14–20 Oct*: what came back, what held, what moved (a Wheel proposal awaiting an answer is mentioned), one question for the week ahead. Under 250 words, no scores, no streaks, no invitation to keep talking. Written on the model in use (never harmonism.io's hosted one), from the week's messages, practices and check-ins, Wheel moves and the conversation context; through the Telegram bot when the window is closed. A week with fewer than three messages gets none. One review in any six days, whichever device or page writes it: a review being written is logged before it is composed, and the synced `outreach` record unites the devices' logs. *Write the last seven days now* writes one at once.
30. **A conversation by voice (1.13, after Sesame's and Pi's).** The button beside the microphone: Lodestone listens, hears the end of what was said by the silence after it (1.1 s, the room's noise measured as it listens), writes it out (on this computer, or through the provider chosen in Settings → Dictation), sends it, speaks the answer in the voice chosen, and listens again. Speaking over the answer stops it (its voice, and its writing if it is still being written) and Lodestone listens; what was under way no longer moves the conversation on. Each turn is an ordinary message: the crisis gate, the care layer, the day's limits; a crisis answer, the crisis line after a care moment, or the pause bell ends the conversation by voice so it can be read; an answer that could not be given ends it with the words left in the message box. Esc, *End*, or two minutes of silence end it. On the web app and the phone the speech model is the browser's own copy, as for dictation.

If the model will not load, the window says why in plain words: a damaged file offers *Download it again*, a missing part *Download the missing part*, too little memory a smaller model, an unsupported custom model says so. The engine's log sits behind *Details*.

## How it works

The window's pages come from a private server in the app at `127.0.0.1:47863` (fixed, because browser storage is bound to it):

| Path | Served from |
|---|---|
| `/` | the library (`src/site.js`): `resources/site/en` shipped, `<userData>/site/<lang>` downloaded or updated |
| `/lodestone-app/` | the web app; `corpus/` from `<userData>/updates/corpus` when updated |
| `/v1`, `/lodestone-app/v1` | the engine, OpenAI-compatible |
| `POST /companion-api.php` | `src/companion.js`: the site's companion answered locally, streamed in the Anthropic event shape the site's script reads |
| other `*.php`, `/member/…` | a page linking to harmonism.io; a `.php` holding only HTML (Wheel, assessment) is served from the library |

Every library page gets a small script: the anonymous message counter reads 0, and the account links are hidden.

| File | Role |
|---|---|
| `src/main.js` | Window, menu, config, IPC, links to harmonism.io rewritten to the library. |
| `src/engine.js` | llama.cpp `llama-server` as a hidden child process: 32,768-token window, one slot, thinking off. Answers only Lodestone's own server: a key made at each start (sent by `server.js` and `companion.js`, never to the page), no `/slots`, CORS to `https://lodestone.invalid` (as Lode desktop 0.10.1). Runs Prism ML's build instead for a model that needs it (`dir`). Stale engines from a crash are stopped at next launch. |
| `src/gguf.js` | What a model file needs, read from its tensor types: `prism` for Prism ML's ternary packings, `unknown` for types no engine here reads. Ported unchanged from Lode desktop. |
| `src/models.js` | Catalog (repo, every file's size and SHA-256), memory tiers, and `fromHuggingFace()` for pasted links. |
| `src/download.js` | Resumable, hash-verified downloads through Electron's network stack; `downloadModel()` for multi-part models. |
| `src/companion.js` | Crisis gate, keyword retrieval, witness and governor blocks and the full backbone, imported from `../app/js/` so the two companions cannot drift. |
| `src/site.js`, `src/updates.js` | Library packs and the update check. |
| `src/weblookup.js` | Search and page reading for *Look this up online*. |
| `src/remote.js` | A rented model under the practitioner's key: presets, model list, the test request, and the OpenAI → Anthropic Messages translation behind `/v1`. |
| `src/telegram.js` | The practitioner's own Telegram bot: long polling, pairing, HTML formatting, daily practice check-ins. Answers come from a hidden page of the app in bridge mode (`?bridge=telegram`, `app/js/main.js`), so they share the window's memory and harness. |
| `src/launcher.*`, `setup.css`, `src/phone.*` | Setup, model, library and phone screens. |
| `engines/` | llama.cpp **b11243** builds: `darwin-arm64` (Metal), `darwin-x64`, `win32-x64-vulkan`, `linux-x64-vulkan` (Vulkan loaded dynamically, CPU fallback; Windows carries the MSVC runtime app-locally). |
| `site-en/` | The English library, unpacked from `en.tar.gz` (see below). `pack-library.js` packs it into `build-res/site-en.tar.gz`, which ships as `resources/site/` and is unpacked into the data folder on first launch: loose files with accented names (…žižek, …maté) broke the Mac signature, since a Mac stores those names in another Unicode form than the one signed on Linux. |

### Hardening (1.12, after Lode's audit)

- **Settings never lost to a bad write.** `desktop.json` is written beside itself and renamed into place (mode 0600); an unreadable one is kept aside as `desktop.json.corrupt-<time>` and the practitioner told, not overwritten by the defaults. The phone sync store likewise.
- **The server serves Lodestone's pages only.** A request whose `Host` is not an address, `localhost` or a `.local` name is refused (DNS rebinding: an attacker's name pointed at 127.0.0.1); a request whose `Origin` is another site is refused, so a web page in the browser cannot spend the model or the rented key through `127.0.0.1:47863`. Lodestone's own page, a phone's browser on the Wi-Fi (its own origin) and the Android app (`NATIVE_ORIGINS`) pass.
- **Only Lodestone's own setup pages get the setup bridge.** `launcher.html` and `phone.html` by their exact files; the window does not navigate to any other local page (a stray HTML file dropped on a library page), and such a page gets no bridge.
- **Permissions:** Lodestone's own origin may use the microphone (never the camera), notifications and copying; nothing else is granted, to no other page, the hidden Telegram page included.
- **The engine** gets the environment without keys, tokens, secrets, passwords or `LLAMA_ARG_*`; its log is in the data folder (`engine.log`), not the shared temporary folder.
- **The life book** writes each note through a temporary file of its own name (a crash's leftover never blocks the next write), keeps the note's mode, and makes `.backups/` folder by folder, refusing a link where a folder goes.
- **One send at a time:** a second Enter while the first still checks (the spending limit, the privacy gate) is not a second message. Esc closes an open menu or card before it stops an answer, and clears the conversation search first. Announcements go to screen readers through the toast (`role="status"`), no longer the whole conversation as it streams.

Not taken from Lode: a Content Security Policy for the app page (its wasm runtimes and model loading need testing first); its approvals, sandbox and snapshots, which belong to an agent that edits files.

## Signing

Without paid certificates each system asks once: macOS → System Settings → Privacy & Security → *Open Anyway*; Windows → SmartScreen → *More info* → *Run anyway*. `build-mac.sh` signs with Lodestone's own self-signed certificate (`keys/lodestone-mac-signing.p12`, never published) without the hardened runtime (required: it has no Team ID), and ad hoc only when that file is absent; with a Developer ID in the keychain it signs with the hardened runtime and notarizes when `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD` and `APPLE_TEAM_ID` are set.

Why the certificate, and never ad hoc on Linux either (`rcodesign sign` with no `--p12-file` signs ad hoc): the saved sign-in and keys are encrypted under the keychain item *Lodestone Safe Storage*, which macOS hands only to the app it trusts. An ad-hoc signature's identity is the hash of that one build, so every update is a stranger to the keychain: it asks for the login password twice at the first launch (the app and its network helper), and a denied or dismissed prompt leaves the sign-in unreadable, so Lodestone asks to sign in again. Signed with the same certificate, every version has the designated requirement `identifier "io.harmonism.munai-offline" and certificate root = H"c2ef8d1a38aff5026836bdcd2c6efd0397ab3119"`: *Always Allow*, given once, holds from then on.
