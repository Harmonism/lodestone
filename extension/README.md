# Lodestone — Harmonist Companion (Browser Extension)

The Lodestone sprite, beyond harmonism.io. Lodestone accompanies you across the web: absorb any page, receive its summary, and get the Harmonist reading — the page's claims held against Harmonism at the register the page calls for: the doctrine when it is an idea or argument, the individual path and the Wheel when it is a life, and the Architecture when it is a civilization.

## Architecture

One source of truth. The extension holds no prompt, no doctrine, no API key — everything routes to the existing `companion-api.php` on harmonism.io, which owns the system prompt, doctrinal backbone, RAG over the vault, crisis layer and classifier. Since 2.0 the memory is not the server's: it is the practitioner's Lodestone memory, held in the extension and synced with their other devices.

- `content.js` — the sprite (ported SVG + core animation states from `LodestoneSprite.astro`) and chat panel, in a closed shadow root. Since 2.0 it is not a declared content script: the worker injects it (`activeTab` + `scripting`) only into a page where the practitioner calls Lodestone, by the toolbar button or the right-click item, so the extension runs on no page by default and asks for no access to all sites. A second click dismisses it; the tab's conversation returns when it is called again. Extracts main content Readability-style (visible text blocks, noise stripped, ~11.5k chars).
- `background.js` — the only network path, an MV3 module worker. Fetches `companion-api.php` from the service worker (host_permissions ⇒ CORS-exempt), parses the SSE stream, relays deltas to the content script over a Port. Signed in, every turn goes through `lib/held.js` (`heldFetch`): the memory travels with the request and comes back updated, and the reading is kept as its own conversation named for its page (`ext-<hash of the URL>`).
- `lib/` — Lodestone's memory modules (`store.js`, `sync.js`, `syncwire.js`, `phone.js`, `sse.js`, `native.js`, `hp.js`, `held.js`), copied from `lodestone/app/js` by `build.sh` and never edited here (`lib/FROM-APP.txt` names the source). `session-store.js` keeps the harmonism.io sign-in in `chrome.storage.local`, where `phone.js` would use `localStorage`.
- `readings.html/js` — **Readings (2.1, October 19, 2026)**: every page Lodestone was asked about, with its address, date, number of exchanges and kind (*Harmonist reading*, passage, absorbed, summary, question, told from the panel's own prompts); search over titles, addresses and text; a kind filter; each reading opened in full (Markdown escaped first; only http(s) links kept), copied, or forgotten; *Export as Markdown* for the readings shown. Opened from *All readings* in the panel's header, the toolbar icon's right-click menu, and the options page (the worker opens the tab: `lodestone-open-readings`). Its data comes from the worker (`lodestone-readings`: `list`, `forget`, `forget-anonymous`, `keep-anonymous`), which answers only the extension's own pages, never a content script. Signed in, the readings are the memory's page conversations (`ext-…`), and *Forget* deletes one on every synced device; anonymous, see below.
- `options.html/js` — how to call Lodestone, the harmonism.io sign-in and Lodestone sync (the presence toggle and per-site hidden list of 1.x are gone with the always-present sprite). Reached in one click since 2.2.8: *Sign in* (signed out) or *Settings* (signed in) in the panel's header, *Sign in, key and settings* in the toolbar icon's right-click menu, and opened by itself once on first install.

### Identity tiers

- **Anonymous (default)** — `anonymous: true`, zero persistence server-side, 60 messages/hour per IP (the server's existing abuse backstop). On top of that, the extension enforces the conversion architecture client-side: **7 lifetime messages** (`chrome.storage.local` counter), soft nudge at 4, then a gate card → free account (5/day, server-enforced once signed in); beyond that, the free Lodestone app on the practitioner's own model or key (no paid tier).
- **Memory (opt-in, 2.0)** — the options page signs in to the harmonism.io account (email and password, Supabase; no cookie permission) and turns on Lodestone sync: with no copy yet, one switch starts it; with one, the options page shows a one-time code to type on a device already synced, which lets the browser in (no passphrase since October 19, 2026; `lodestone/README.md` § Sync). Joining brings the website conversation, the learned profile and the reading into the extension. A synced browser lists other devices waiting to be let in and shows the recovery code on asking. Conversations then feed the same memory as the website, the app and Lodestone Desktop. The Art. 9 consent gate is honored: if the server returns the consent envelope, the card's button records the consent on the account (`lodestone-consent`, with the sign-in) and retries, or the practitioner continues anonymously. 1.2's cookie link (`harmonia_client_id`) is gone; a 1.2 install sending a client id without a sign-in is answered anonymously once the server is deployed.

### Server-side counterpart

`companion-api.php` recognizes `source: "extension"` (patches of 2026-08-02):

1. `pageContext` cap raised 4,000 → 12,000 chars for extension clients (arbitrary web pages, not site slugs).
2. `pageUrl` used verbatim (site clients get `https://harmonism.io` prefixed) and the `<current_page>` framing tells Lodestone the practitioner is on the open web with the sprite alongside.
3. CORS: `moz-extension://` and `safari-web-extension://` origins are echoed back — Firefox and Safari background fetches are CORS-checked (no Chromium host_permissions bypass).

Deploy the patched file through the usual `deploy-companion.sh` / `post-build.sh` flow. Until it's deployed, the extension still works — absorbs are just truncated at 4,000 chars and the prompt says "on harmonism.io."

## Browsers

- **Chrome / Brave / Edge / Opera** — one Chromium build (`manifest.json`). Dev install: `chrome://extensions` → Developer mode → Load unpacked → this folder. Store: Chrome Web Store (Brave and Opera install from there); Edge Add-ons is an optional free second listing of the same zip.
- **Firefox 121+** — same code, `manifest.firefox.json` (event-page background, gecko id, options_ui). Host permissions are opt-in on Firefox MV3: the options page requests them inside the memory-link gesture, and chat itself works without them because the server allows `moz-extension://` origins. Dev install: `about:debugging` → This Firefox → Load Temporary Add-on → the firefox zip. Store: addons.mozilla.org (free, review required).
- **Safari** — see `SAFARI.md` (Xcode converter; deliberate second wave, iOS being the interesting target).

Build store-ready zips with `./build.sh` → `dist/lodestone-chromium-<v>.zip`, `dist/lodestone-firefox-<v>.zip`.

Lodestone is not injected on harmonism.io / integralharmonysystem.com — the site already carries its own.

The packages of 2.2.3 were rebuilt with them; 2.2.1 and 2.2.2 were never uploaded. 2.2.4 (October 23, 2026): the sprite's bottom facet a shade under its neighbours in both skins (`--sp-f4` light `#B6A4D3`, dark `#5E5381`), in `content.js` and the three icons; not yet packaged or uploaded. The addons.mozilla.org listing icon was replaced with the new `icon128.png` the same day (Edit Product Page → Images).
- Anonymous readings are kept on this browser alone (2.1): when an anonymous turn ends, the worker keeps the question, the answer, the page's title and address and the kind in `chrome.storage.local` (`readings-anon`, the newest 300), for the Readings page. Never sent anywhere. Off with *Keep anonymous readings on this browser* on that page (`readings-anon-keep`), which also offers *Forget every anonymous reading*.
- Anonymous conversation history is per tab and site, kept by the worker in the extension's `chrome.storage.session` (never the page's `sessionStorage`, which the page's scripts could read; 2.0 removes what 1.x left there), cleared when the tab closes, capped at 20 turns — matching the site's anonymous tier. Signed in, the reading is kept in the memory, one conversation per page.
- Tested in Chromium (`harmonia-astro/tools/test-held.py`, extension part: sign-in, joining the memory, a reading answered and kept, anonymous kept nowhere before 2.1). 2.1's Readings page, October 19, 2026, with the unpacked extension loaded in Chromium and harmonism.io intercepted: signed out, the page says so; an anonymous Harmonist reading through the worker's port is kept with its kind, title and address and listed; switched off, the next is not kept; *Forget* removes it. With a stubbed worker: listing, search, kind filter, the full reading (a `<script>` shown as text, a `javascript:` link dropped, a site-relative link sent to harmonism.io), export with both addresses, the switch sent. Not yet run: the signed-in list from a real memory, the panel's *All readings* button, the toolbar menu item, and the refusal of a content script's request. Firefox's module event page is not yet tried.
- Anonymous lifetime counter lives in `chrome.storage.local` (`anonCount`); clearing extension storage resets it — acceptable, the IP rate limit backstops abuse.
- Markdown in responses: harmonism.io links, bold, italics only — everything else is escaped.
